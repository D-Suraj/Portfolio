08 / Engineering approach
01

Start with ground truth.

Use retrieved source context, protocol traces, or packet captures before forming a theory about system behavior.

02

Break across boundaries.

Separate retrieval, identity, persistence, service, and model concerns so each failure can be isolated.

03

Design the failure path.

Timeouts, retries, validation, and controlled updates matter because external APIs and probabilistic outputs will fail.

04

Debug to the layer that owns it.

If a Python symptom originates in native code, authentication policy, or a network protocol, follow it there.
